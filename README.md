# Task Tracker Telegram Bot

Telegram-бот для [Task Tracker](https://github.com/execc0/task-tracker) - REST API для управления задачами.
Бот является клиентом к основному сервису и позволяет регистрироваться, авторизовываться и управлять своими задачами прямо в Telegram.

Бот доступен по ссылке: https://t.me/TaskTrackerTGBot

### Связанные проекты: 



>  **Task Tracker** — основной API, содержит в себе непосредственно всю логику, хранит задачи и пользователей в БД PostrgeSQL.
>  Репозиторий: https://github.com/execc0/task-tracker

> **Task Tracker monitoring** - Prometheus, Node Exported и Grafana для сбора и показа метрик.
> Репозиторий: https://github.com/execc0/task-tracker-monitoring

## Как это устроено

Бот не хранит данные о задачах самостоятельно — он ходит за ними в основной [Task Tracker API](https://github.com/execc0/task-tracker),
подписывая часть запросов через HMAC и передавая внутренний ключ (`X-Internal-API-Key`) для обхода ограничения rate limiter'a основного API.
Диалог с пользователем построен на конечном автомате: текущий шаг и промежуточный ввод хранятся в Redis (`UserStateService`),
а переходы между меню и обработчиками распределяют `BotCommandDispatcher` и `BotCallbackQueryDispatcher`.

### Навигация по кнопкам

Всё перемещение между разделами бота — через inline-кнопки под сообщением, а не текстовые команды.
Каждая кнопка отправляет `callback_data` (например, `menu:task`, `task:get:list`, `state:return`),
который разбирает `BotCallbackQueryDispatcher` и вызывает нужный обработчик — открытие меню, следующий шаг сценария или переключение страницы задач.
Сообщение с меню при этом не дублируется, а редактируется на месте (ID активного меню хранится в Redis), поэтому чат не засоряется.

### Хранение состояний пользователя

Каждый диалог (регистрация, логин, создание задачи и т.д.) описан значением `enum UserState` с номером шага,
ссылкой на предыдущий шаг и текстом подсказки. Сам прогресс и промежуточный ввод хранятся в Redis (`user:state:*`, `user:tmp:*`) с TTL 15 минут, чтобы незавершённые диалоги не оставались в системе.

###  Прогресс-бары

Многошаговые сценарии сопровождаются прогресс-баром, который рассчитывается по текущему и общему числу шагов из `UserState`:

```
🟩🟩🟩⬜⬜ Шаг 3/4
```
Помимо этого во время пошаговых операций пользователь так же имеет возможность отменить операцию или перейти к предыдущему шагу:

<img width="245" height="103" alt="image" src="https://github.com/user-attachments/assets/c32b0372-d1e8-4335-8dd4-b077f46fdb0d" />

### Хранение авторизационных токенов

После логина или регистрации JWT-токен сохраняется в Redis через `TokenHandlerService` (ключ `chat_id:auth {chatId}`, TTL 30 минут)
и используется сервером бота для запросов к Task Tracker API от имени пользователя. Токен нигде не хранится постоянно и удаляется по истечении TTL или явно — при `/unlink`.

### Автоматическое удаление сообщений

Сообщения пользователя, связанные с вводом состояний или выполнением команд автоматически удаляются, чтобы не засорять чат и не оставлять в нём конфиденциальную информацию (логины и пароли).
Сообщения от бота так же удаляются по истечении времени.

## Запуск проекта

### Требования

- Java 21+
- Docker & Docker Compose
- Запущенный экземпляр [Task Tracker API](https://github.com/execc0/task-tracker)

### 1. Клонировать репозиторий

```
git clone https://github.com/execc0/task-tracker-TGBot.git
cd task-tracker-TGBot
```

### 2. Создать файл `.env` в корне проекта

```
bot_token=your_telegram_bot_token
API_handshake_token=your_hmac_secret
INTERNAL_API_KEY=your_internal_api_key
```

- `bot_token` — токен бота, выданный [@BotFather](https://t.me/BotFather)
- `API_handshake_token` — секрет для подписи запросов (HMAC, base64)
- `INTERNAL_API_KEY` — ключ для доверенного взаимодействия с Task Tracker API
- `SENTRY_LINK` - ссылка от Sentry (для сбора трейсов вызовов и ошибок)

### 3. Запустить инфраструктуру

```
docker-compose up -d
```

Поднимет Redis, используемый для хранения состояний диалога.

### 4. Запустить приложение

```
./gradlew bootRun
```

## Возможности бота

Основная навигация (меню задач, профиль, пагинация, отмена/возврат) выполняется по inline-кнопкам, текстовыми командами вызываются только вход в систему и старт диалогов, перечисленных ниже.

## 🔑 Аутентификация

| Команда     | Описание                                    |
| ----------- | -------------------------------------------- |
| `/start`    | Приветственное меню                          |
| `/register` | Регистрация нового пользователя и привязка Telegram-аккаунта |
| `/login`    | Вход в существующий аккаунт                  |
| `/unlink`   | Отвязать Telegram-аккаунт от Task Tracker     |

## 📋 Задачи (меню «📝 Задачи»)

| Кнопка / действие   | Описание                                  |
| -------------------- | ------------------------------------------ |
| Создать задачу        | Пошаговое создание: название, описание, приоритет (`LOW` / `MEDIUM` / `HIGH`), статус |
| Мои задачи             | Постраничный список задач с кнопками «Вперёд» / «Назад» |
| Статус задачи          | `TODO` / `IN_PROGRESS` / `DONE`             |

## 👤 Профиль (меню «👤 Профиль»)

| Кнопка / команда | Описание                          |
| ------------------ | ---------------------------------- |
| `/menu`             | Открыть главное меню               |
| Профиль             | Просмотр и изменение имени, username, email, пароля |
| Удалить аккаунт     | Удаление аккаунта с подтверждением |

## Мониторинг

Actuator поднят на отдельном порту (`management.server.port=9091`) и отдаёт `health` и `metrics` для сбора Prometheus. Ошибки выполнения дополнительно репортятся в Sentry.
